# SkillSpector

[SkillSpector](https://github.com/NVIDIA/skillspector)로 스킬의 보안 위험(프롬프트 인젝션, 데이터 유출, 악성 코드, 공급망 위험)을 검사한다. 이 스킬은 검사만 한다. 설치 위치와 방법은 다루지 않는다.

## 설정

LLM 분석 제공자는 레포 루트 `.env`의 `SKILLSPECTOR_PROVIDER` 값으로 관리한다. SkillSpector는 `.env`를 직접 읽지 않으므로, 실행할 때마다 아래 명령으로 값을 읽어 명령 앞에 붙인다.

```bash
grep -E '^SKILLSPECTOR_PROVIDER=' .env | tail -n 1 | cut -d= -f2- | tr -d "\"' \r"
```

- `.env`를 `source`하거나 셸로 실행하지 않는다. `SKILLSPECTOR_PROVIDER` 줄만 읽고, 다른 줄의 값은 읽거나 출력하지 않는다.
- `.env` 파일이 없거나 `SKILLSPECTOR_PROVIDER` 줄이 없으면 값이 비어 있는 것으로 본다.
- 쓸 수 있는 값: `openai`, `anthropic`, `anthropic_proxy`, `bedrock`, `minimax`, `nv_build`, `nv_inference`, `ollama`, `azure_openai`, `openai_compatible`, `gemini`, `claude_cli`, `gemini_cli`, `opencode_cli`. 목록은 `skillspector scan --help`의 `SKILLSPECTOR_PROVIDER` 설명으로 확인한다. `codex_cli`는 목록에 있어도 비활성화되어 있으므로 틀린 값으로 본다.
- 값이 비어 있거나 위 목록에 없으면 `SKILLSPECTOR_PROVIDER=`를 붙이지 말고 `--no-llm`을 붙여 LLM 분석 없이 실행한다. 빈 값을 그대로 붙이면 SkillSpector가 기본 제공자(NVIDIA)로 파일을 보낸다.
  - 결과는 아래 "결과 처리"대로 처리하되, 보고 맨 앞에 "LLM 분석 없이 정적 분석만 했다"는 것과 그 이유(값이 비어 있음 또는 틀린 값 `<값>`)를 알리고 `.env`의 값을 채워 달라고 요청한다.
- 제공자의 API 키는 이 스킬이 `.env`에서 읽지 않는다. 키는 각자의 환경변수로 둔다.

SkillSpector가 설치되어 있지 않으면 사용자에게 설치할지 묻는다. 설치 명령은 `uv tool install --python 3.12 git+https://github.com/NVIDIA/skillspector.git`이다(`uv` 필요). `--python 3.12`를 빼면 Python 3.14 환경에서 의존성 `yara-python` 빌드가 C 컴파일러 없이 실패한다.

## 외부로 코드 전송

LLM 분석은 검사 대상 파일 내용을 제공자 서버로 보낸다.

- **라이브러리 스킬을 설치하려고 검사할 때만** LLM 분석을 쓴다.
- 그 외의 모든 검사(팀이 만든 스킬, 이 레포의 코드)는 `--no-llm`으로 실행한다. `claude_cli`, `gemini_cli` 제공자도 외부 서버로 보내므로 예외가 아니다.

## 검사 대상

- 스킬 폴더만 지정한다. 레포 루트나 `backend/`, `frontend/`를 통째로 검사하지 않는다.
- 라이브러리 스킬은 에이전트가 읽는 폴더에 넣기 전에 레포 밖의 임시 폴더에서 검사한다.
- 스킬이 여러 개 들어 있는 대상은 `--recursive`를 붙인다.

### 검사한 버전 고정

검사한 코드와 설치하는 코드가 같아야 한다.

1. 라이브러리 스킬을 레포 밖의 임시 폴더에 clone한다.
2. 검사 전에 커밋 SHA(`git rev-parse HEAD`)를 기록한다. 버전 태그나 패키지 버전이 있으면 함께 기록한다.
3. 그 폴더를 검사한다. Git URL을 바로 검사하지 않는다.
4. 결과를 보고할 때 검사한 커밋 SHA와 버전을 함께 알리고, 설치는 그 커밋이나 버전으로 하도록 안내한다.
5. 설치할 수 있는 버전이 검사한 커밋과 다르면, 설치하지 말고 바뀐 버전으로 다시 검사한다.
6. 설치 방법이 커밋이나 버전 고정을 지원하지 않으면, 막지 말고 "설치할 때 받는 코드가 검사한 코드와 다를 수 있다"는 문제를 사용자에게 알린 뒤 설치할지 묻는다.

```bash
# 라이브러리 스킬 (설치 전, LLM 분석 허용)
git clone <Git URL> <레포 밖 임시 폴더>
git -C <레포 밖 임시 폴더> rev-parse HEAD
SKILLSPECTOR_PROVIDER=<설정 값> skillspector scan <레포 밖 임시 폴더> --fail-on-incomplete --format json --output <레포 밖 리포트 파일>

# 라이브러리 스킬, 설정 값이 비어 있거나 틀린 경우
skillspector scan <레포 밖 임시 폴더> --no-llm --fail-on-incomplete --format json --output <레포 밖 리포트 파일>

# 팀 스킬 (외부 전송 금지)
skillspector scan <스킬 폴더> --no-llm
```

- `--fail-on-incomplete`는 일부 분석이 끝나지 않으면 종료 코드 1로 끝나게 한다. 라이브러리 스킬 검사에는 항상 붙인다.
- 종료 코드 1은 점수가 50을 넘을 때도 나오므로, 원인은 JSON 리포트로 구분한다. 아래 "결과 처리"에서 쓰는 필드는 다음과 같다.
  - `risk_assessment.score`: 위험 점수
  - `analysis_completeness.is_complete`, `coverage_percent`: 분석 완료 여부와 범위
  - `analysis_completeness.ledger_exceptions[].path`: 부분 검사로 끝난 파일
  - `metadata.llm_requested`, `metadata.llm_available`, `metadata.llm_error`: LLM 분석 요청 여부, 실행 여부, 실패 이유

### 자동 업데이트 끄기

새 스킬은 자동 업데이트가 꺼진 형태로 설치한다. 자동 업데이트는 검사 없이 새 코드를 받아오기 때문이다.

- 설치를 안내할 때 자동 업데이트를 끄는 옵션이나 설정까지 함께 안내한다. 도구가 기본으로 자동 업데이트를 켜면 설치 직후 끄도록 안내한다.
- 자동 업데이트를 끌 수 없는 설치 방법이면, 막지 말고 "이후 업데이트가 검사 없이 들어온다"는 문제를 사용자에게 알린 뒤 설치할지 묻는다.

### 업데이트

이미 설치한 라이브러리 스킬을 업데이트할 때도 새로 설치할 때와 같이 검사한다.

1. 업데이트하기 전에 사용자에게 업데이트할지 묻는다.
2. 업데이트하기로 하면 새 커밋으로 위 "검사한 버전 고정" 순서대로 검사한다.
3. 검사 결과를 아래 "결과 처리" 표대로 처리한 뒤 업데이트한다.
4. 업데이트한 뒤에도 자동 업데이트는 꺼진 상태로 둔다.

## 결과 처리

검사 결과와 별개로 아래 "외부 통신 확인"을 먼저 한다. 그다음 위에서부터 차례로 확인하고, 처음 해당하는 줄대로 처리한다.

| 결과 | 처리 |
| --- | --- |
| 종료 코드 2 (검사 오류) | 설치하지 말라고 하고 오류를 사용자에게 보고한다 |
| LLM 분석 요청했으나 실행 안 됨 (`llm_requested`가 `true`인데 `llm_available`이 `false`) | 검사 오류로 보고 설치 여부를 묻지 않는다. `llm_error`를 보여 주고, 제공자 설정과 API 키(또는 CLI 로그인)를 확인해 달라고 요청한다 |
| 점수 51 이상 (DO NOT INSTALL) | 설치하지 말라고 하고 결과를 사용자에게 보고한다 |
| "외부 통신 확인"의 설치 금지 항목 발견 | 점수와 상관없이 설치하지 말라고 하고, 발견한 파일과 줄을 보고한다 |
| 분석 불완전 (`is_complete`가 `false`) | 아래 "분석 불완전 경고"를 보여 주고 설치 여부를 묻는다. 점수가 21~50이면 발견 항목도, 외부 전송이 있으면 "외부 전송 경고"도 함께 보여 준다 |
| 점수 21~50 (CAUTION) | 발견 항목을 사용자에게 보여 주고 설치 여부를 묻는다. 외부 전송이 있으면 "외부 전송 경고"도 함께 보여 준다 |
| 점수 0~20 (SAFE) | 검사를 통과했다고 알리고, 검사한 커밋 SHA와 버전을 함께 전달한다. 단, 외부 전송이 있으면 통과로 보지 않고 "외부 전송 경고"를 보여 준 뒤 설치 여부를 묻는다 |

### 분석 불완전 경고

분석이 끝나지 않았다는 것은 일부 코드의 동작이 검증되지 않았다는 뜻이다. 다른 설명보다 먼저, 눈에 띄게 알린다.

- 경고는 답변 맨 앞에 둔다. 요약이나 다른 발견 항목 뒤에 묻지 않는다.
- 검사 범위(`coverage_percent`)와 부분 검사 파일 수를 숫자로 적는다.
- 부분 검사 파일은 두 묶음으로 나눠 전부 나열한다.
  - **실행되는 파일**: 훅, 스크립트, MCP 서버처럼 설치 후 실행되는 파일(`.js`, `.ts`, `.py`, `.sh` 등과 훅·플러그인 설정이 가리키는 파일)
  - **그 외 파일**: 문서, 테스트, 벤치마크 등
- "대체로 안전해 보인다"처럼 경고를 약하게 만드는 말을 덧붙이지 않는다.
- 사용자가 명확히 설치하겠다고 답한 경우에만 설치를 안내한다. 답이 모호하면 다시 묻는다.

```
⚠️ 경고: 검사가 끝나지 않은 파일이 있습니다

검사 범위 82.5% (171개 중 141개만 완전 검사, 30개 부분 검사)
이 파일들의 일부 동작은 검증되지 않았습니다. 설치하면 검증되지 않은 코드가 실행될 수 있습니다.

실행되는 파일 (N개)
- hooks/ponytail-activate.js
- ...

그 외 파일 (N개)
- tests/hooks.test.js
- ...

그래도 설치할까요? 설치하려면 "설치"라고 답해 주세요.
```

### 외부 통신 확인

설치 후 실행되는 파일(훅, 스크립트, MCP 서버)과 그 실행 명령(훅 설정, MCP 서버 설정)을 직접 읽고 아래 세 가지를 찾는다. SkillSpector 발견 항목 중 `MCP Rug Pull`, `Supply Chain`, `Data Exfiltration`, `Dangerous Code Execution`, `YARA Match` 분류가 실행되는 파일을 가리키면 함께 확인한다.

검사는 설치하는 순간의 코드만 본다. 실행 중에 외부에서 받아오는 내용은 검사할 수 없고, 검사한 커밋으로 고정해도 바뀔 수 있다. 실행 중에 받아오는 공식 CDN 파일이 나중에 변조되어 악성 코드가 퍼진 사례가 있다.

#### 1. 실행 중 외부 코드 받아오기 → 설치 금지

- CDN(`unpkg`, `jsdelivr`, `cdnjs` 등), `raw.githubusercontent.com`, 그 밖의 URL에서 스크립트, 프롬프트, 규칙, 설정을 받아와 실행하거나 에이전트에 넣는 코드
- 버전을 고정하지 않은 `npx`, `uvx`, `pip install` 같은 실행 명령. 실행할 때마다 최신 패키지를 받는다
- 예외: 받아오는 내용의 SHA-256 해시가 코드에 고정되어 있고, 받은 내용의 해시가 다르면 쓰지 않는 경우. 정확한 버전을 고정한 패키지 실행 명령(예: `npx -y <패키지>@1.2.3`)

#### 2. 숨긴 주소, 동적 코드 실행 → 설치 금지

- 숫자 배열, base64, 문자 코드 변환, 문자열 조합으로 복원한 문자열을 네트워크 주소로 쓰는 코드
- 받아온 문자열이나 복원한 문자열을 `eval`, `new Function`, `vm.runIn*Context`, `node -e`, `python -c` 등으로 실행하는 코드
- `<script>` 태그를 동적으로 만들어 넣는 코드
- 해당하지 않는 경우: 고정된 문자열 리터럴만 실행하는 코드(예: `vm.runInNewContext('re.test(s)', ...)`), 경로 구분자처럼 주소나 코드가 아닌 용도로 문자를 변환하는 코드(예: `String.fromCharCode(92)`로 역슬래시 처리)

#### 3. 외부 전송 경고 (설치 여부 묻기)

- 외부로 데이터를 보내는 요청(webhook, POST, 분석 도구 전송 등)은 전부 해당한다. 보내기만 하는 요청도 포함한다.
- 항목마다 파일과 줄, 보내는 주소(설정값이면 그 설정 이름과 기본값), 보내는 데이터, 기본으로 켜져 있는지를 적는다.
- 강조 방식은 "분석 불완전 경고"와 같다. 답변 맨 앞에 두고, 완화하는 말을 붙이지 않고, 사용자가 "설치"라고 명확히 답할 때만 설치를 안내한다. 분석 불완전 경고와 함께 나오면 이 경고를 먼저 둔다.

```
⚠️ 경고: 설치 후 외부로 데이터를 보내는 코드가 있습니다

- hooks/band/register.tsx:176 — 설정 `webhookUrl`(기본값: 비어 있음, 꺼짐)로 작업 기록(비용, 토큰, 작업 이름)을 POST로 보냄

설정하지 않으면 보내지 않지만, 설정하면 위 데이터가 그 주소로 나갑니다.
그래도 설치할까요? 설치하려면 "설치"라고 답해 주세요.
```
